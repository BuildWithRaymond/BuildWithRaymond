# Profile maintenance

The README is the public profile. Artwork is standalone SVG in `assets/`, including the supplied Hernbrode identity. No game sprites, captures, credentials or private source files are included.

- `README.md` is the primary source for introduction, native Markdown content, links, and responsive artwork choices. After an edit, run `python3 scripts/render_static_profile.py` to regenerate `STATIC.md` before validation. Do not maintain a second hand-edited copy.
- Brand artwork is generated manually by `scripts/render_brand_assets.py`. Update its layout/copy/motion, then regenerate instead of editing output that a later manual run will overwrite. From the Agency workspace, run `python github-profile/scripts/render_brand_assets.py --brand-dir public/brand`; from another checkout, pass the directory containing the approved identity files. This manual generator remains separate from the daily public-metadata updater.
- The exact supplied Hernbrode wordmark and H monogram belong to the owner's supplied identity. The generator copies the existing outlined geometry from `logo-cream.svg`, `mark-cream.svg`, and `mark-black.svg` without redrawing or replacing it. Supply those approved source files when regenerating; they are not fetched from another service.
- Profile artwork uses self-contained, repeating CSS construction sequences. A short draw leads into a hold, a fade, and a reset while the moving layer is hidden. Logos and essential text remain present. `@media(prefers-reduced-motion:reduce)` disables motion and displays the complete final composition immediately. No scripts, external stylesheets, or animated text counters are used.
- The generated equivalent [static profile](STATIC.md) uses separate completed artwork without animation styles or SMIL. Its generator removes animated picture sources, retains normal static mobile sources and image fallbacks, preserves native copy, and replaces the top choice with a return link to the animated profile. The workflow regenerates it before validation and commits updates alongside activity data, preventing copy drift.
- The workflow refreshes `assets/activity.svg`, `assets/activity-mobile.svg`, `assets/activity-static.svg`, and `assets/activity-mobile-static.svg` daily from the same public repository summary and UTC date. All four generated files are committed together. No personal access token is needed.
- Totals exclude private repositories, records without confirmed public visibility, forks, and the profile repository. Language counts measure repositories, not lines of code. Stars are stars across those original public repositories, not client or business results.
- Keep activity rendering in the same brand system: ink `#0B0B0B`, charcoal `#1F1F1F`, cream `#F3EEE7`, restrained orange `#FF6A00`, and muted text `#BDB6AD`. Daily updates use `scripts/update_activity.py`; editing only the generated SVGs will be overwritten. The 480 px mobile variant uses at least 22 px labels and 64 px counts so it remains readable when GitHub scales it to a narrow article column. README `<picture>` selects the compact variant; the desktop contact sheet keeps the wide variant.
- Activity artwork repeats a 4.2-second divider construction: draw, hold, fade, and reset while hidden. The permanent short orange mark stays unchanged. Default SVG attributes and reduced motion both show the finished static divider. Static activity files are generated from the same completed attributes with styles and animation elements removed. Repository totals, stars, language names, counts, and proportion bars never animate or simulate changes.
- Profile changes and manual workflow runs render a static contact sheet for review in the workflow log.
- The preview canvas height is calculated from all rendered assets, including the tallest card in each row. The existing `SVG_PREVIEW_BASE64:` log output is preserved. To also save a local PNG, run `python3 scripts/render_preview.py --output /tmp/profile-preview.png` in an environment with CairoSVG and Pillow. The workflow installs these dependencies on Ubuntu; Windows also needs Cairo's native runtime.
- Manually generated brand artwork in the README is pinned to the published design commit `331f30e763622be098971a307c4b8496efdc335c` so cached branch URLs cannot show a previous design. After an artwork or motion change, publish that artwork commit first, then update its README image references to the new full commit SHA.
- All four dynamic activity references use the explicit `refs/heads/main` path so daily refreshes remain visible without changing a design pin. Keep these references unpinned. Bump the optional safe version token (for example, `?v=motion-loop-20261027`) when their artwork or timing changes to avoid a stale cached design; the branch reference still follows daily data refreshes. The token changes cache identity, not data or animation behavior.
- README and STATIC image sources may use relative `assets/...` paths or raw GitHub URLs belonging to this profile on `main`, `refs/heads/main`, or a full commit SHA. Only those exact raw GitHub profile asset URLs may have one optional `v` query token containing 1–64 ASCII letters, digits, underscores, or hyphens. Other query fields, fragments, relative-path queries, other branches, and external hosts are rejected. Validation checks every `<img>` and `<picture><source srcset>` candidate in both pages when present, resolves only files within local `assets/`, and never fetches remote resources.
- Run `python3 -m unittest discover -s tests -v` and `python3 scripts/validate_profile.py` before publishing edits.

Keep upstream attribution for forked community projects. Do not publish private repository names, private implementation details, credentials, or unsupported business claims in this profile. A private portfolio remains separate from the public profile.

The intended website domain is omitted from public links until the owner confirms that the website is live and the destination is correct. Do not infer domain ownership or a working mailbox from the brand name.
